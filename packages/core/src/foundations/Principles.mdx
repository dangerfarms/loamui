# Principles

Five ideas hold LoamUI together. Each is grounded in a reference and enforced
somewhere (by the cascade, a lint rule, a CI gate, or review), not just asserted
here.

## Three primitives, in cascade order

The library offers three things, and they are applied by cascade order, not by
specificity fights:

```css
@layer loamui.tokens, loamui.elements, loamui.components;
```

- **[Tokens](?path=/docs/foundations-tokens--docs)**: the design decisions, as
  semantic custom properties.
- **[Element styles](?path=/docs/foundations-element-styles--docs)**: enhanced
  defaults on native elements, so unstyled HTML already looks right.
- **Components**: composed on top, each owning only its own scope.

Because the order is declared once, your own unlayered CSS always wins, and you
can slot an `app` layer after the library's without `!important`. The five
pillars below are the ideas that hold these three together.

## 1. Native CSS

Real elements carry semantics; native CSS carries styling. A button is a
`<button>`, a dialog is a `<dialog>` opened with `showModal()`, an accordion is
`<details>`/`<summary>`, a separator is an `<hr>`. Behaviour the browser already
implements (focus containment, Escape handling, find-in-page reveal, single-open
disclosure) is inherited, not re-written. ARIA is used only where the platform
has no word for something.

The payoff is a library with nothing running at runtime: no CSS-in-JS, no
styling engine, no serialization cost. The styles are plain, static CSS.
Grounded in Google Chrome's Modern Web Guidance.

## 2. Modern CSS

`@layer` for order, `@scope` for encapsulation, `light-dark()` and container
queries for adaptation: additive styles that lean on the cascade instead of
fighting it. Selectors are scoped with `@scope`, not BEM; the encapsulation is
the at-rule's job, not the class name's. Each property is set once under
mutually-exclusive conditions, and the only override permitted inside the
library is `elements → components`. Colour is `oklch()`; relationships between
colours are `color-mix()` and relative-colour syntax, so the whole palette
derives from a few inputs and a rebrand is a one-line token change. The
ModernCSS rule set.

## 3. Composition

Parts, not prop soup. Compound components expose named parts (`Modal.Root` /
`Trigger` / `Popup` / `Title` / `Close`) that you arrange in your markup, rather
than one component configured through a wall of props. Swapping the underlying
element (a router link for a built-in `<a>`) goes through a `render` prop.
Icons and loaders are ordinary children the component detects. You assemble the
shape you need from small pieces instead of configuring a monolith, and the
structure stays where you can see it and rearrange it.

## 4. Contextualism

LoamUI components take no `variant`, `size`, or `color` props. A region declares
what it means, and every control inside adapts:

- **Meaning** comes from a `--loam-context` region: declare `--loam-context:
  danger` on an area and every component inside adopts it.
- **Size** comes from container queries and fluid `cqi` tokens: a control in a
  narrow column sizes itself; at 16rem or below a button goes full-width.
- **Contents** are detected with `:has()` (an icon child, a rendered error
  message), never passed as a slot prop.

This is the entire status-and-size API: set once on a region, never repeated as
a prop on each control. A success alert is an `Alert` in a `success` region. See
[Contextualism](?path=/docs/foundations-contextualism--docs) for the full
mechanism, and the live
[Contexts](?path=/story/foundations-contexts--danger-context) demo.

## 5. Accessible & gatekept

Semantic HTML, managed focus, keyboard support, and the reader's preferences as
the baseline. Colour scheme is followed natively through `light-dark()`. Motion
is opt-in: animation lives only inside `@media (prefers-reduced-motion:
no-preference)`, so the absence of motion needs no override. Forced-colour
palettes are honoured with system colours. Target size, contrast ratios and
focus visibility are engineered and tested; see
[Accessibility](?path=/docs/foundations-accessibility--docs).

None of the above survives on good intentions. The palette is contrast-audited
in CI (4.5:1 text, 3:1 boundaries and focus rings, both schemes); CSS is linted
for the rules above; every component ships axe and keyboard interaction tests
that run here in a real browser. What a tool can verify, a tool verifies.
